`git log --oneline --stat` — показывает краткую историю коммитов (хэш и тему) вместе со статистикой измененных файлов (какие файлы менялись и сколько строк добавлено/удалено). Нужна для быстрого обзора динамики проекта.
* `git diff HEAD~2 HEAD -- calc.py` — показывает построчную разницу в файле `calc.py` между состоянием два коммита назад (`HEAD~2`) и текущим (`HEAD`). Позволяет увидеть, как развивался код.
* `git show HEAD~1` — показывает метаданные и полный патч (изменения) конкретного коммита (в данном случае — предыдущего `HEAD~1`). Нужна для детального изучения одного коммита.
* `git log -S"строка"` — ищет коммиты, в которых количество упоминаний заданной строки изменилось (добавилось или удалилось). Помогает найти, когда именно в коде появился или исчез конкретный метод или переменная.
* `git blame calc.py` — выводит файл построчно, указывая для каждой строки хэш коммита, автора и дату последнего изменения. Нужна, чтобы понять, кто и зачем внедрил эту строчку кода.

* `git log` исследует саму историю (список событий/коммитов).
* `git diff` сравнивает состояния кода между разными точками (коммитами, ветками или рабочей директорией).
* `git show` отображает объект целиком — обычно конкретный коммит и его изменения.
`git restore <file>` — откатывает незакоммиченные изменения в рабочей директории до состояния последнего коммита (`HEAD`).
* `git restore --source=<commit> <file>` — извлекает состояние файла из указанного коммита и копирует его в рабочую директорию.
Если применить обычный `git restore`, все текущие незакоммиченные правки в файле сотрутся безвозвратно. Если применить `git restore --source=...`, незакоммиченные правки также будут перезаписаны состоянием файла из указанного источника (`source`).
`git revert HEAD` — создает **новый коммит**, который вносит изменения, строго противоположные указанному коммиту (симметрично отменяет код).
Отличие от `git reset --hard` и безопасность
* `git reset --hard <commit>` «отматывает» указатель ветки назад, буквально стирая последующие коммиты из видимой истории.
* В опубликованной (публичной/удаленной) истории `git revert` безопаснее, потому что он **не переписывает историю**, а движется вперед. Если стереть коммиты через `reset` и отправить в общий репозиторий, у других разработчиков возникнет конфликт историй. `revert` же просто добавляет новый коммит, который бесконфликтно скачается всеми коллегами
* **Тег (Tag)** — это статическая «закладка», жесткий указатель на конкретный коммит. Он остается привязанным к этому коммиту навсегда (пока его не удалят вручную) и не двигается при создании новых коммитов. Идеален для релизов и версионирования (например, `v1.0`).
* **Ветка (Branch)** — это динамический указатель. Когда вы находитесь на ветке и делаете новый коммит, указатель ветки автоматически сдвигается вперед, на этот новый коммит. Используется для активной разработки.
